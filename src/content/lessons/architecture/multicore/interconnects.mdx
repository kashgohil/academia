The MESI lesson used a **bus**: one shared set of wires. Every cache sees every request on the bus, in the same order. This is simple, and it makes ordering easy. But a bus does not scale. Each transaction occupies the whole bus, and each cache must look up each request. Long shared wires are also slow.

Chips with tens of cores use a **network** instead. A network connects each core to a few neighbors with point-to-point **links**. A message moves from one router to the next. Each step over one link is a **hop**. These chips also replace broadcast snooping with **directories**.

## Topologies

| Topology | Hops | Links | Where |
|---|---|---|---|
| Bus | 1 | 1 (shared) | small SMPs; the conceptual model |
| Crossbar | 1 | n² | small core counts, GPUs between SMs and L2 slices |
| Ring | ~n/4 | n | Intel client CPUs and older Xeons (ring bus through L3 slices) |
| 2D mesh | ~2√n/3 | ~2n | Intel Xeon since Skylake-SP, many-core research chips |
| Chiplets + switch | 2 levels | — | AMD EPYC/Ryzen: core chiplets connected via an I/O die (Infinity Fabric) |

Three numbers describe a network:

- **Latency**: the number of hops, multiplied by the delay of one hop.
- **Bisection bandwidth**: the capacity across a cut through the middle of the network. For a mesh, about $\sqrt{n}$ links cross the cut.
- **Cost**: wires, chip area and power.

Each design is a compromise between these three numbers.

## Directory protocols

A **directory** records two things for each line: its coherence state and its set of **sharers**. The sharer set is often a bit vector, with one bit for each core. The directory entry is kept at the **home node** of the line: the L3 slice or memory controller for that address. A miss goes to the home node. The home node then does one of these:

- If no core owns the line, it sends the data from memory or L3.
- If one core owns the line (M, E or O), it forwards the request to that owner.
- For a write, it sends invalidations only to the cores in the sharer set. Each of these cores sends an acknowledgement. The writer gets permission only after it has all the acknowledgements.

<DirectoryDemo />

1. Click **All read, then C0 writes**. The last write sends 7 invalidations and gets 7 acknowledgements: 16 messages with the request and the grant.
2. Select **Snooping broadcast**. The same 9 accesses make 63 lookups in other caches, against 33 directory messages.
3. Click **C2 and C5 take turns to write**. After the first write, each write needs 5 messages: a request, a forward to the owner, the data, an invalidation and an acknowledgement.
4. Click **C3 writes, C6 reads**. The home node forwards the read to C3, the owner. C3 sends the data to C6 and writes the line back to memory: 4 messages.

The number of messages for a miss depends on how many cores **share** the line. It does not depend on how many cores **exist**. But a directory has costs too. One bit per core for each line needs much storage, so real designs keep a few pointers, or one bit for a group of cores. Each miss also takes an extra hop through the home node. The protocol is harder to verify, because messages can race through a network that does not keep them in order.

Most current servers use a **snoop filter**. It is a structure like a directory. It records which cores *might* hold a line, so that only those cores are snooped.

## What this means for software

- Core-to-core latency is not the same for all pairs, even in one socket. Tools such as `core-to-core-latency` measure it. Cores in opposite corners of a mesh are farther apart than neighbors.
- AMD chips put their cores on several chiplets (CCDs). Sharing a line between two chiplets costs much more than sharing it inside one. Keep threads that communicate a lot in the same core complex (CCX).
- Software pays the coherence cost for each sharer at each write. Data that is mostly read is cheap to share. Data that is written and shared does not scale.
