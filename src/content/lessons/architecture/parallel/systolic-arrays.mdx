A GPU feeds its arithmetic units from a register file. Each operand travels from the register file to a unit and back. A **systolic array** removes most of that travel. It is a grid of small **processing elements** (PEs). Each PE does one multiply-accumulate (MAC) per cycle and passes its inputs to its neighbours through registers. Data enters at the edges, and each value is used by every PE that it passes.

Kung and Leiserson described systolic arrays in 1978 ("Systolic Arrays (for VLSI)"). Kung explained the idea in "Why Systolic Architectures?" (IEEE Computer, January 1982). The name comes from the heart: data is pumped through the array in a regular beat. The main argument is about bandwidth. An array of $n \times n$ PEs does $n^2$ MACs per cycle, but it reads only about $2n$ values per cycle from its edges.

## Weight stationary, cycle by cycle

In a **weight-stationary** array, PE(r, c) holds one weight $W_{rc}$ for the whole computation. Row m of the input matrix X enters from the left, one value per row of PEs. Each value moves one PE to the right per cycle. Partial sums move one PE down per cycle. The output $Y_{mc} = \sum_r X_{mr} W_{rc}$ leaves at the bottom of column c.

The inputs must arrive with a **skew**. Row r of the array receives its value of input row m in cycle $m + r$. So the value meets the partial sum that comes down from row $r - 1$ at the correct moment.

## Fill, drain and the choice of dataflow

The time of a run is

$$
T = S + R + C - 2
$$

for a stream of S vectors on an array of $R \times C$ PEs. The useful work is $S \cdot R \cdot C$ MACs, so the utilization is $S / (S + R + C - 2)$. The array is efficient only when the stream is much longer than the array is wide. On a 256 × 256 array with a stream of 256 rows, the run takes 766 cycles, and the utilization is only 33%.

Each dataflow keeps one operand in place and streams the other two:

| Dataflow | Stays in the PE | Moves | The streamed dimension |
|---|---|---|---|
| Weight stationary | one weight | inputs right, partial sums down | batch (rows of X) |
| Output stationary | one output sum | A right, B down | the inner dimension k |
| Input stationary | one input value | weights and partial sums | output columns |

Weight stationary is good when the same weights are used for many inputs: inference with a large batch. Output stationary is good when the inner dimension is long: the sums never leave the array until they are complete. Real accelerators combine these choices with buffers that hold the next tile while the current one computes.

## The Google TPU v1

Jouppi et al. described the first Tensor Processing Unit in "In-Datacenter Performance Analysis of a Tensor Processing Unit" (ISCA 2017). Its center is a **Matrix Multiply Unit** of 256 × 256 = 65,536 8-bit MACs at 700 MHz. That gives 92 tera-operations per second. The paper describes the dataflow of this lesson. The weights are preloaded from the top, data flows in from the left, and the partial sums go to 4 MiB of 32-bit accumulators below.

The unit holds one 64 KiB tile of weights plus a second for double buffering. The weights come from 8 GiB of DDR3 memory at 34 GB/s. The activations live in a 24 MiB on-chip **Unified Buffer**. The chip was made in a 28 nm process.

Now compare the two rates. At 34 GB/s and 700 MHz, the memory delivers about 48.6 bytes per cycle. One 64 KiB tile of weights takes 1,349 cycles to arrive. A tile is used once for each input row of the batch. So unless the batch has about 1,350 rows, the array waits for weights. The paper puts the ridge point of its roofline at 1,350 operations per byte of weight memory.

This is a model with three inputs from the paper: the array size, the clock and the weight bandwidth. It ignores the activation traffic and the time of the other units. The paper measured the real numbers. Its Table 3 reports that the six production applications used 23% of the MACs of the array on average. The two MLPs used 12.5% and 9.4%, and the best CNN used 78.2%.

TPU v2 to v5 used arrays of 128 × 128 PEs. Norrie et al. describe TPU v2 and v3 in IEEE Micro (2021). TPU v2 has a 128 × 128 systolic array per matrix unit, and TPU v3 has twice as many matrix units. Smaller arrays waste less on small or odd-shaped layers. TPU v6e (Trillium) went back to 256 × 256 arrays. The training chips also use high-bandwidth memory in place of DDR3.

## What this means for your code

- On any matrix unit, the batch (or the reused dimension) must be large enough to cover the time to load the weights.
- Pad or group small layers. A layer that is much smaller than the array wastes most of it.
- Compute the time to load a weight tile and compare it with the rows that use it. This is the roofline of the [SIMD lesson](/architecture/parallel/simd-and-vector-units) in the units of the accelerator.
