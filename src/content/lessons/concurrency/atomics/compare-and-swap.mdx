`compare_exchange(expected, desired)` atomically does: *if the value is still `expected`, replace it with `desired` and report success; otherwise report the current value.* With it you can build any atomic update, such as max, a linked-list push or a state-machine transition, and every lock-free data structure. Herlihy showed CAS is *universal* in exactly this sense, which plain loads and stores are not.

## The retry loop

Every CAS-based update follows one shape:

```rust
let mut cur = x.load(Ordering::Relaxed);
loop {
    let new = f(cur);
    match x.compare_exchange_weak(cur, new, Ordering::AcqRel, Ordering::Relaxed) {
        Ok(_) => break,
        Err(actual) => cur = actual, // someone else won; retry with what they wrote
    }
}
```

```zig
var cur = x.load(.monotonic);
while (x.cmpxchgWeak(cur, f(cur), .acq_rel, .monotonic)) |actual| {
    cur = actual; // null means success; otherwise we get the current value back
}
```

- **Weak vs strong**: `compare_exchange_weak` may fail *spuriously*, even when the value matched. On LL/SC machines (ARM, RISC-V) the store-conditional fails if anything disturbed the line. Inside a loop, use weak; for a single attempt, use strong.
- **Two orderings**: one for success (the full RMW), one for failure (just a load). Failure can't be `release`, because nothing was written.
- **ABA**: CAS checks the *value*, not whether it changed. If it went A → B → A in between, CAS succeeds, which breaks pointer-based structures whose nodes were freed and reused. The lock-free module covers tagged pointers, hazard pointers and epochs.

## Contention

<CasContentionDemo />

Each failed CAS is wasted work *and* another trip of the cache line between cores. In this simulation the attempts per increment grow from 1.0 with one thread to about 2.7 with 8 and 3.7 with 16. Randomized exponential backoff after a failure cuts that to about 2.0 and 2.4. On real hardware each attempt also includes a cross-core line transfer, so the cost per increment grows faster still.

Practical rules:

- **Prefer a dedicated RMW** (`fetch_add`, `fetch_or`, `exchange`) when one exists. It can't fail and it's one instruction.
- **Test-and-test-and-set**: spin on a plain `load` until the lock looks free, *then* CAS. Loads can share the line; every CAS needs it exclusive.
- **Back off** under contention, and on x86 use a pause hint while spinning (`_mm_pause`, `std::hint::spin_loop()` in Rust, `std.atomic.spinLoopHint()` in Zig).
- **Shard** hot counters per thread or per core and sum them when read.
