Every ordering rule in this module exists to build one relation: **happens-before**. It decides two things. First, which writes a read is allowed to see. Second, whether a program has a **data race**, meaning two conflicting accesses (same location, at least one a write, at least one non-atomic) not ordered by happens-before. In C, C++, Rust and Zig a data race is undefined behavior for the whole program, not just a wrong value.

Compare **Plain data, relaxed flag** (race) with **release/acquire flag** (race-free, and `r0` is always 42). Then:

- **Happens-before is transitive**: T2 never touches T0's flag, yet reads T0's plain write safely through T1.

- **Spinlock** vs **relaxed spinlock**: mutexes are exactly this. Unlock is a release and lock is an acquire.

## Building the relation

<Steps>
<div><b>Sequenced-before</b>: within one thread, program order.</div>
<div><b>Synchronizes-with</b>: a release operation (or fence) in thread A, and an acquire operation (or fence) in thread B that reads the value A wrote, or a later value in its release sequence.</div>
<div><b>Happens-before</b>: the transitive closure of the two. A happens-before B if a chain of program order and synchronizes-with edges leads from A to B.</div>
<div><b>Visibility</b>: a read sees the last write that happens-before it, or a write it isn't ordered with. That second case is legal only for atomics, and is exactly where relaxed reads get their freedom.</div>
</Steps>

## The guarantee that makes this usable

**SC for DRF** (sequential consistency for data-race-free programs): if a program has no data races and uses only seq_cst atomics, every execution looks like a simple interleaving of the threads. You can reason about it with the mental model from the SC column. Weaker orders keep the "no race" part but give up the "simple interleaving" part. That's the real trade you make when you write `relaxed`.

## Finding races in practice

The explorer detects races the same way **ThreadSanitizer** does: each thread carries a vector clock (one counter per thread), release/acquire pairs merge clocks, and an access races if the clock of the conflicting access isn't covered.

- C/C++: `-fsanitize=thread`. Rust: `RUSTFLAGS="-Zsanitizer=thread"` on nightly. Go: `go test -race`. Zig: `-fsanitize-thread`.
- Sanitizers only check the schedules that actually ran. Model checkers explore *all* schedules, like the explorer here: **loom** (Rust), **GenMC** and **CDSChecker** (C/C++), and TLA+ for designs.
- Rust's type system rules out data races on safe references at compile time (`Send`/`Sync`). Ordering mistakes between atomics are still yours to make.
