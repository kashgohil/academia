A **lock-free stack** is a linked list with an atomic `head` pointer. An atomic variable is a variable that threads read and write in one indivisible step. Each change uses **compare-and-swap** (CAS). `CAS(head, old, new)` writes `new` only if `head` still holds `old`, and it reports success or failure. A thread prepares its change privately and then publishes it with one CAS on `head`. If the CAS fails, another thread changed the stack first, so the thread reads `head` again and tries again.

R. Kent Treiber described this stack at IBM in 1986. It is still the simplest real lock-free data structure. It also contains every problem that the rest of this module solves.

```rust
fn push(&self, v: T) {
    let n = Box::into_raw(Box::new(Node { v, next: null_mut() }));
    loop {
        let h = self.head.load(Acquire);
        unsafe { (*n).next = h };                       // private: no other thread can see n yet
        if self.head.compare_exchange_weak(h, n, Release, Relaxed).is_ok() { return; }
    }
}
fn pop(&self) -> Option<T> {
    loop {
        let h = self.head.load(Acquire);
        if h.is_null() { return None; }
        let next = unsafe { (*h).next };                // reads a node that another thread can free
        if self.head.compare_exchange_weak(h, next, Acquire, Relaxed).is_ok() {
            return Some(unsafe { take_value(h) });      // and when is it safe to free h? (see below)
        }
    }
}
```

1. Keep 4 threads in **Lock step**. Each arrow goes from a private node to the node that its thread saw as head. A red arrow is a stale view: head moved, so that CAS will fail.
2. Count the attempts: 4 pushes need 10 CAS operations. The last thread fails 3 times before it succeeds.

## Why it is correct

- **Linearizability.** An operation is linearizable if it seems to take effect at one instant between its start and its end. For a Treiber push or pop, that instant is the successful CAS. For a pop on an empty stack, it is the load that saw null. So each concurrent history is equal to some sequential order of these instants (Herlihy and Wing, 1990).
- **Private until published.** A thread writes a new node only while no other thread can see it. The release CAS then publishes the contents of the node. Release means that the earlier writes become visible to a thread that reads `head` with acquire.
- **Retry on interference.** The CAS checks the exact head on which the change is based. So a thread with an old view cannot overwrite the update of another thread.

## Progress guarantees

| Guarantee | Meaning | Treiber stack |
|---|---|---|
| Blocking (locks) | one stalled thread can stop all threads | no |
| Obstruction-free | a thread that runs alone finishes | yes |
| **Lock-free** | some thread always finishes within a bounded number of steps of the whole system | **yes**: a failed CAS means that another CAS succeeded |
| Wait-free | *every* thread finishes within a bounded number of its own steps | no: one thread can fail again and again |

Lock-free does not mean fast. Under heavy contention, CAS retries can make a good lock faster (see the Compare-and-swap lesson). Lock-free means that **no thread can block the other threads**. This is true even if a thread is descheduled, killed, or runs in a signal handler.

## The real difficulty

Look at `pop` again. Between `h = head.load()` and the read of `(*h).next`, another thread can pop `h`. If that thread **frees** `h`, the read uses freed memory. If the allocator **reuses** that memory for a new node, the CAS can succeed when it must fail. This is the ABA problem, the subject of the next lesson.

Garbage-collected languages, such as Java, Go and C#, avoid both problems. They free nothing while a reference to it exists. C, C++, Rust and Zig need a **memory reclamation scheme**: a rule that decides when no thread can still use a removed node.
