A lock-free stack is a linked list whose `head` is an atomic pointer. Every change is prepared privately and then published with a single compare-and-swap on `head`. If the CAS fails, someone else changed the stack first, so you re-read and try again. R. Kent Treiber described it at IBM in 1986. It is still the simplest real lock-free structure, and it contains every problem the rest of this module solves.

```rust
fn push(&self, v: T) {
    let n = Box::into_raw(Box::new(Node { v, next: null_mut() }));
    loop {
        let h = self.head.load(Acquire);
        unsafe { (*n).next = h };                       // private: n isn't visible yet
        if self.head.compare_exchange_weak(h, n, Release, Relaxed).is_ok() { return; }
    }
}
fn pop(&self) -> Option<T> {
    loop {
        let h = self.head.load(Acquire);
        if h.is_null() { return None; }
        let next = unsafe { (*h).next };                // ← reads a node another thread may free
        if self.head.compare_exchange_weak(h, next, Acquire, Relaxed).is_ok() {
            return Some(unsafe { take_value(h) });      // and when can h be freed? (see below)
        }
    }
}
```

## Why it's correct

- **Linearizability.** Each operation appears to take effect at one instant: its successful CAS (or, for a pop on an empty stack, the load that saw null). Any concurrent history is equivalent to some sequential order of those instants (Herlihy and Wing, 1990).
- **Private until published.** A pushed node is only written while nobody else can see it, and the release CAS publishes its contents.
- **Retry on interference.** Because the CAS checks the exact head we based our change on, a stale view can't overwrite someone else's update.

## Progress guarantees

| Guarantee | Meaning | Treiber stack |
|---|---|---|
| Blocking (locks) | a stalled thread can stop everyone | no |
| Obstruction-free | a thread running alone finishes | yes |
| **Lock-free** | some thread always finishes in a bounded number of system-wide steps | **yes**: a failed CAS means another one succeeded |
| Wait-free | *every* thread finishes in a bounded number of its own steps | no: one unlucky thread can retry forever |

Lock-free doesn't mean fast: under heavy contention the CAS retries (Compare-and-swap lesson) can make a good lock faster. It means **no thread can block the others**, even when it's descheduled, killed, or running in a signal handler.

## The real difficulty

Look at `pop` again. Between `h = head.load()` and reading `(*h).next`, another thread can pop `h`, and if it **frees** `h` we read freed memory. If that memory is **reused** for a new node, the CAS can even succeed when it shouldn't. That's the ABA problem, the next lesson. Garbage-collected languages (Java, Go, C#) avoid both, because nothing is freed while a reference exists. In C, C++, Rust and Zig the solution is a **memory reclamation scheme**.
