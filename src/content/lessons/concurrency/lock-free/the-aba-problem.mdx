CAS asks "is the value still what I saw?", but the question you care about is "has *anything* changed since I looked?" Those differ when a value goes **A → B → A**. With pointers this happens easily: a node is popped and freed, and the allocator hands the same address back for a new node that gets pushed. To CAS, the head is "still A".

1. Run **Play the ABA schedule** without tags. Watch the free list: the most recently freed node is the next one allocated, as in real allocators. The checks panel reports values 1 and 8 lost or returned twice.
2. Turn on **tagged pointers** and run it again. `head` now carries a version number that every successful CAS increments. T0 saw `A·v0`, but by then head is `A·v4`, so the CAS fails, T0 retries and correctly pops 8.
3. Even with tags, step through T0 slowly: it still **reads A.next after A was freed** (a use-after-free) before its CAS fails.

## How common is it?

<StressDemo configs={STRESS_ABA} />

Under random schedules, freeing immediately breaks the stack in most runs: lost and duplicated values, a corrupted list, double frees. Tags eliminate every *logical* failure, but the use-after-free reads remain. In this simulation the freed node is still mapped memory, so the stale read is harmless. In a real program the allocator may have returned that page to the OS (segfault) or reused it as a different type (you read garbage and act on it).

## Fixes and their limits

| Fix | How | Limit |
|---|---|---|
| **Tagged pointers** | CAS a (pointer, counter) pair: `cmpxchg16b` on x86-64, or pack the counter into unused pointer bits (16 spare high bits with 48-bit addresses, or low bits from alignment) | Doesn't stop reads of freed memory; the counter can wrap |
| **LL/SC** | ARM `ldxr`/`stxr`: the store fails if the line was written at all, so no ABA on the location itself | Not exposed portably; C++ and Rust offer CAS |
| **Type-stable memory** | Never return nodes to the general allocator; recycle them only as nodes (e.g. a pool) | Needs tags anyway; memory is never given back |
| **Safe memory reclamation** | Don't reuse a node while anyone might still hold its address: hazard pointers, epochs, RCU | Extra bookkeeping per operation (next two lessons) |
| **Garbage collection** | The address can't be reused while a reference exists | Not available in C, C++, Rust or Zig without a library |

The robust answer is the last row but one: if no node is freed while a thread might hold its address, it can't come back as "A" either. Reclamation fixes ABA and use-after-free together.
