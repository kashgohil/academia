IP has no way to report a problem inside its own header. The **Internet Control Message Protocol** (ICMP, RFC 792) fills this gap. A router that drops a packet can send an ICMP message back to the source and say why. Hosts also use ICMP to test reachability. ICMP travels inside IP, with protocol number 1. IPv6 has its own version, ICMPv6 (RFC 4443), with protocol number 58.

Many administrators see ICMP as a risk and block it. This lesson shows what then breaks: traceroute loses its answers, and path MTU discovery turns into a black hole that hangs connections.

## The messages

Every ICMP message starts with a type (8 bits), a code (8 bits) and a checksum (16 bits) over the whole message. The rest depends on the type.

| Type | Code | Meaning | Sent by |
|---|---|---|---|
| 8 / 0 | 0 | echo request / echo reply (ping) | any host |
| 3 | 0, 1 | destination unreachable: no route to the network or host | a router |
| 3 | 3 | port unreachable: no socket listens on that UDP port | the destination |
| 3 | 4 | fragmentation needed, but DF is set | a router |
| 11 | 0 | time exceeded: TTL reached 0 | a router |
| 11 | 1 | time exceeded: fragment reassembly timed out | the destination |
| 5 | 0 to 3 | redirect: use a better first hop | a router |

ICMPv6 uses other numbers for the same ideas. Type 1 is destination unreachable, 2 is Packet Too Big, 3 is time exceeded, and 128 and 129 are echo. It also carries functions that IPv4 does elsewhere, such as neighbour discovery, which replaces ARP. An IPv6 network that blocks all ICMPv6 does not work.

1. Look at **Time exceeded**. After the 8-byte ICMP header comes a full copy of the dropped packet's IP header, then its UDP header with both ports.
2. Choose **Unreachable: fragmentation needed**. The second word now carries the next-hop MTU, here 1400.
3. Choose **Echo request**. It has no quoted packet: an identifier and a sequence number match each reply to its request.

The quote also lets a NAT translate an error back to the inside host. It reads the ports in the quoted header and finds the mapping. RFC 1812 asks routers to quote as much of the original packet as fits in a 576-byte ICMP message. In the demo, an error with the minimum quote is 56 bytes on the wire. That is 20 bytes of IP header, 8 of ICMP header and 28 of quote.

Hosts and routers follow a few rules so that errors do not cause more errors. They never send an ICMP error about an ICMP error, about a fragment other than the first, or about a broadcast. They also rate-limit errors. Linux limits the errors of the types in `net.ipv4.icmp_ratemask` to each destination. On average it sends one per `net.ipv4.icmp_ratelimit`, 1000 ms by default, with bursts of up to 6. The default mask 6168 covers types 3, 4, 11 and 12, so echo replies are not limited.

## Traceroute

Van Jacobson wrote traceroute in 1988 with a simple trick. It sends a probe with TTL 1, and the first router drops it and answers "time exceeded". It sends TTL 2 and hears from the second router, and so on. When a probe finally reaches the destination, the destination answers "port unreachable", because the probe goes to an unlikely UDP port, starting above 33434. The source of each answer names one hop, and the time to the answer gives a round-trip time.

```c
// One traceroute probe: a UDP packet with a chosen TTL.
int ttl = hop;
setsockopt(udp_fd, IPPROTO_IP, IP_TTL, &ttl, sizeof ttl);
dst.sin_port = htons(33434 + seq);   // classic traceroute: a new port per probe
sendto(udp_fd, buf, len, 0, (struct sockaddr *)&dst, sizeof dst);
// The answer arrives on a raw ICMP socket: type 11 from a router, type 3 code 3 from the target.
```

The design has a hidden problem. Many routers spread traffic over several equal-cost paths, and they keep each flow on one path by hashing its addresses and ports. Classic traceroute changes the destination port for every probe. So each probe is a new flow, and probes of the same hop can take different paths.

1. With classic probes, the output shows A1 and B1 at hop 2, and R3 at hops 3 and 4. The demo finds 4 links in the output that do not exist, and 2 false loops.
2. Choose **Paris: same flow**. Every probe hashes to the same branch, and the output is one real path, with no false links.

4. Turn on **B1 sends no ICMP errors**. A silent router appears as a row of stars, but the probes still pass through it.

Augustin and others measured these effects in "Avoiding traceroute anomalies with Paris traceroute" (IMC 2006). Their tool keeps the first four bytes of the transport header fixed, which hold the ports, because load balancers hash them. It changes the UDP checksum instead, to tell the probes apart.

Read traceroute output with care for other reasons too. A round-trip time includes the return path, which can differ from the forward path. It also includes the time that the router's slow path takes to build the ICMP message. So a high time at one hop says little, if later hops do not show it too.

## Path MTU discovery

A TCP sender wants packets as large as the path allows, but it cannot see the smallest MTU on the path. **Path MTU discovery** (RFC 1191) finds it with ICMP. The sender sets DF on every packet. A router whose next link is too small drops the packet and returns "fragmentation needed". The low 16 bits of the second word carry the next-hop MTU. The sender lowers its estimate for that destination and sends smaller packets.

The sender caches the estimate. Linux keeps it for 600 seconds (`net.ipv4.route.mtu_expires`) and then tries larger packets again. RFC 1191 says that a host must never lower its estimate below 68 bytes. It must also wait at least 5 minutes before it tries to raise it. IPv6 works the same way with ICMPv6 Packet Too Big (RFC 8201). There, it is the only option, because IPv6 routers never fragment.

1. With the defaults, R2 drops the first four 1,500-byte packets and sends four ICMP messages. S lowers its MSS to 1,360 and finishes at 182 ms.
2. Turn on **Firewall in front of S drops all ICMP**. Every large packet dies, and S backs off after each timeout. It gives up after 25.4 s and 7 timeouts. This is a **PMTU black hole**.
3. Keep the firewall and turn on **MTU probing**. After the first timeout, S drops to an MSS of 1,024 and the transfer completes at 402 ms.
4. Turn the probing off and turn on **MSS clamping**. The tunnel router rewrote the MSS in the handshake to 1,360, so no large packet is ever sent, and the transfer ends at 152 ms.
5. Turn on **DF off**. R2 now fragments each large packet into two, and C reassembles them.

The black hole is common enough to have its own RFC: RFC 2923 (2000) lists it among TCP's problems with PMTUD. RFC 4890 lists ICMPv6 Packet Too Big as traffic that firewalls must not drop. Operators and stacks use three defences:

- **MSS clamping.** A router at a tunnel rewrites the MSS option in TCP handshakes, so that both ends start with segments that fit. It helps only TCP.
- **Packetization-layer PMTUD** (PLPMTUD, RFC 4821, 2007). The transport probes with larger packets and treats their loss as a size problem, with no need for ICMP. Linux controls it with `net.ipv4.tcp_mtu_probing`. The value 0 (the default) turns it off, 1 uses it after a black hole is detected, and 2 always uses it. Probing starts from `tcp_base_mss`, 1024 by default.
- **Datagram PLPMTUD** (DPLPMTUD, RFC 8899, 2020) brings the same idea to UDP transports such as QUIC.
