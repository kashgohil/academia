There are about 4.3 billion IPv4 addresses, and far more devices. Most homes, offices and phone networks therefore hide many hosts behind one public address. A **network address and port translator** (NAPT, RFC 3022), usually just called NAT, makes this work. It rewrites the source address and port of each outgoing packet, and it remembers the change so that it can undo it for the replies.

NAT is everywhere, so its behaviour matters to every protocol designer. It decides which packets may enter a network, how long a quiet connection survives, and whether two hosts can ever talk directly.

## The translation table

When an inside host sends a packet to the Internet, the NAT looks for a **mapping** for the packet's source address and port. If none exists, it creates one with a free external port on its public address. It rewrites the source to that external address and port, and it updates the IP and TCP or UDP checksums, because both cover the addresses. A reply that arrives at the external port is rewritten back to the inside host.

## Mapping and filtering behaviour

NATs differ in two independent choices. RFC 4787 names them.

| Behaviour | Mapping: which flows share an external port | Filtering: who may send in through a mapping |
|---|---|---|
| endpoint-independent | all flows from one inside address and port | anyone |
| address-dependent | flows to the same remote address | addresses the inside host sent to |
| address-and-port-dependent | flows to the same remote address and port | exact endpoints the inside host sent to |

The older STUN specification (RFC 3489) used other names. A **full cone** NAT has endpoint-independent mapping and filtering. A **restricted cone** filters by address, and a **port-restricted cone** by address and port. A **symmetric** NAT makes a new mapping for each remote address and port.

RFC 4787 also sets requirements for UDP. A NAT must use endpoint-independent mapping, and it must support **hairpinning**: an inside host can reach another inside host through the public address. A UDP mapping must not expire in less than 2 minutes, and 5 minutes or more is recommended. For TCP, RFC 5382 asks that an idle established connection survive at least 2 hours and 4 minutes.

Real defaults vary widely. Linux connection tracking, which `iptables` and `nftables` NAT build on, keeps an unanswered UDP flow for 30 seconds (`nf_conntrack_udp_timeout`). It keeps a UDP flow for 120 seconds once the flow has replies and has lasted over 2 seconds (`nf_conntrack_udp_timeout_stream`). It keeps an established TCP connection for 432,000 seconds, which is 5 days. Home routers and mobile networks are often much shorter. So a long-lived protocol must send **keepalives** more often than the shortest timeout on the path, or the peer can no longer reach it.

## Why NAT breaks peer-to-peer

The Internet was designed so that any host could send to any other host. NAT ends this for hosts behind it. A packet from outside can enter only through a mapping, and only an inside host can create one. Two hosts that are both behind NATs therefore cannot simply connect: each NAT drops the other's first packet.

NAT also breaks protocols that put addresses in their payload, such as FTP or SIP, because the NAT rewrites the header but not the payload. Some NATs carry an **application-level gateway** that rewrites the payload too, but it works only for protocols it knows. For this reason, new protocols avoid carrying addresses in the data.

## Hole punching: STUN, TURN and ICE

Two hosts can still often open a direct path, with help from a server that both can reach. Each host first asks the server what its public address and port look like. This is the job of **STUN** (Session Traversal Utilities for NAT, now RFC 8489). The server tells each host the other's public endpoint. Then both hosts send packets to each other at the same time. Each outgoing packet creates a mapping and a permit in its own NAT, which lets the other host's packets in.

When no direct path works, the hosts use a relay.

**TURN** (Traversal Using Relays around NAT, RFC 8656) gives each host an address on a relay server, which forwards every packet. It always works, but the relay carries all the traffic and adds delay. **ICE** (Interactive Connectivity Establishment, RFC 8445) ties these together. Each host gathers candidate addresses: its local address, its address as STUN sees it, and a TURN relay address. The hosts then test candidate pairs and keep the best pair that works. WebRTC uses ICE for every call.

Hole punching works often, but not always. Ford, Srisuresh and Kegel tested many NATs in 2005. They found that about 82% supported UDP hole punching and about 64% supported it for TCP. TCP is harder: the two SYNs must cross in flight, and some NATs reject an unexpected incoming SYN.

## Carrier-grade NAT

Many ISPs, especially mobile ones, no longer give each customer a public IPv4 address. They put customers behind a **carrier-grade NAT** (CGN), with addresses from the shared range `100.64.0.0/10` (RFC 6598) on the inside. A home router may add a second NAT behind it, so traffic crosses two translations.

A public address has 64,512 ports above 1023. If the CGN gives each customer a fixed block of 1,024 ports, one address serves 63 customers. Fixed blocks make logging cheap: to trace an abuse report, the carrier needs only the block that a customer held, not every mapping. But a customer whose devices open many connections can run out of ports. And when one address carries many customers, a block or a rate limit on that address hits all of them.

```go
// The core of a NAPT, outbound: find or create a mapping, then rewrite.
func (n *NAT) Outbound(p *Packet) {
	key := mapKey{p.SrcIP, p.SrcPort} // endpoint-independent mapping (RFC 4787 REQ-1)
	m, ok := n.table[key]
	if !ok {
		m = &Mapping{ExtPort: n.allocPort(p.SrcPort), Permits: map[endpoint]bool{}}
		n.table[key] = m
	}
	m.Permits[endpoint{p.DstIP, p.DstPort}] = true // for address-and-port filtering
	m.LastUsed = n.now
	p.SrcIP, p.SrcPort = n.publicIP, m.ExtPort
	p.FixChecksums() // the IP header and the TCP/UDP pseudo-header both changed
}
```

IPv6 gives every device a global address, so it needs no NAT. But IPv6 networks keep stateful firewalls with the same filtering ideas. Inbound connections still need a permit, and hole punching still has work to do.
