A **pipe** is a one-way byte stream between two file descriptors. The kernel holds the bytes in its own memory. The writer calls `write`, the reader calls `read`, and neither process knows much about the other.

The structure is `struct pipe_inode_info` in `fs/pipe.c`. It holds a ring of `struct pipe_buffer` entries. Each entry, or **slot**, points at one page. Two counters, `head` and `tail`, mark the used part of the ring. One mutex protects each read and each write.

A new pipe has 16 slots. With 4 KiB pages, its capacity is 65,536 bytes. On arm64, a kernel with 16 KiB pages gives a default pipe of 262,144 bytes.

## The write path

`pipe_write` takes the mutex and then does two things.

First, it tries to **merge**. It computes `total & (PAGE_SIZE - 1)`, the part of the write below one page. If all of this part fits at the end of the last slot, it copies the part there. If only some of it fits, it does not merge at all. A slot can accept a merge only if it has the flag `PIPE_BUF_FLAG_CAN_MERGE`.

Then it fills new slots, one page at a time, until the write ends or the ring is full. If the ring is full, the writer drops the mutex and sleeps on `wr_wait`. The next read that frees a slot wakes it.

```c
// fs/pipe.c, simplified
chars = total_len & (PAGE_SIZE - 1);
if (chars && !was_empty) {
    buf = &pipe->bufs[(head - 1) & mask];
    if ((buf->flags & PIPE_BUF_FLAG_CAN_MERGE) && buf->offset + buf->len + chars <= PAGE_SIZE)
        /* copy chars bytes into the last page */;
}
for (;;) {
    if (!pipe->readers) { send_sig(SIGPIPE, current, 0); ret = ret ?: -EPIPE; break; }
    if (!pipe_full(head, pipe->tail, pipe->max_usage)) { /* take a slot, copy one page */ }
    if (no bytes left) break;
    if (still full) { unlock; wait_event_interruptible_exclusive(pipe->wr_wait, ...); lock; }
}
```

So the capacity in bytes depends on the sizes of your writes. The table shows what the ring does with a 16-slot pipe.

| Write size | Bytes in each page | Bytes when the writer blocks |
|---|---|---|
| 100 | 4000 | 64,000 |
| 2048 | 4096 | 65,536 |
| 2049 | 2049 | 32,784 |
| 3000 | 3000 | 48,000 |
| 4096 | 4096 | 65,536 |

## Blocking and non-blocking

| Call | Ring state | Blocking | `O_NONBLOCK` |
|---|---|---|---|
| `read` | has data | returns what exists, up to the count | same |
| `read` | empty, a writer exists | sleeps | `EAGAIN` |
| `read` | empty, no writer | returns 0 (EOF) | returns 0 (EOF) |
| `write` | room for all | returns the count | same |
| `write` | full, a reader exists | sleeps | `EAGAIN`, or a partial count |
| `write` | no reader | SIGPIPE and `EPIPE` | SIGPIPE and `EPIPE` |

A `read` can return fewer bytes than you asked for. Code that reads a pipe must loop.

## F_SETPIPE_SZ

`fcntl(fd, F_SETPIPE_SZ, n)` changes the capacity. The kernel rounds `n` up to a power of two pages and returns the real size. So a request for 5000 bytes gives 8192. The limit for a normal user is in `/proc/sys/fs/pipe-max-size`, and its default is 1,048,576 bytes. A shrink that cannot hold the current slots fails with `EBUSY`.

The total memory for pipes also has a limit for each user. The default of `/proc/sys/fs/pipe-user-pages-soft` is 16,384 pages, which is 1024 default pipes. After that limit, a new pipe gets only 2 slots. Code that needs a large pipe must check the result of `F_SETPIPE_SZ`.

## PIPE_BUF: when writes stay whole

Several processes can write to one pipe. POSIX promises that a write of at most `PIPE_BUF` bytes is **atomic**: its bytes stay together in the stream. On Linux, `PIPE_BUF` is 4096. The POSIX minimum and the macOS value are both 512.

One limit is important. On Linux, a large write splits only when it must sleep. POSIX allows a split at any byte. So do not build on the Linux behavior. A log line from many processes is safe at 4096 bytes or less. Use a lock or a socket for anything larger.

## EOF, SIGPIPE and pipelines

`read` returns 0 only when the ring is empty and `pipe->writers` is 0. This counter includes each open write end in every process. So one forgotten fd in any process makes the reader wait forever. The lesson on [fork and exec](/os/processes/fork-and-exec) shows how a shell builds `ls | wc` with `pipe`, `fork` and `dup2`. It also shows how this mistake hangs `wc`.

A write with no reader sends **SIGPIPE**, and the default action kills the writer. This is why `yes | head -1` stops: `head` exits, and the next write of `yes` kills it. Shells report that as status 141, which is 128 + 13.

Languages differ here. A Go program dies from SIGPIPE only for a write to fd 1 or fd 2. For other fds, it gets `EPIPE`. Rust's runtime ignores SIGPIPE at startup, so `println!` panics when the pipe closes. A network server usually ignores SIGPIPE and handles `EPIPE`.

## Named pipes

`mkfifo path` makes a **named pipe**, or FIFO. It has a name in the file system, but no data goes to the disk. It uses the same `pipe_inode_info` as a normal pipe. An `open` for reading blocks until a writer opens it, and the same is true the other way. So unrelated processes can meet at a path, and normal file permissions control access.

## Zero copy: splice and vmsplice

A slot points at a page, and the page need not belong to the pipe. Linux uses this for three calls.

- `splice` moves data between a pipe and another fd. From a file, the slot points at a page cache page, with no copy.
- `vmsplice` puts pages of user memory into a pipe. With `SPLICE_F_GIFT`, the caller gives up the page. Without it, the caller must not change the page until the reader is done.
- `tee` copies slot references from one pipe to another, with no copy of the data.

A borrowed page must not take merges. A write that merged into a page cache page would change the file. That was **Dirty Pipe** (CVE-2022-0847). A slot from a splice kept a stale `PIPE_BUF_FLAG_CAN_MERGE` flag, so an unprivileged write could change a read-only file in the page cache. The merge rule in this lesson is the code that it reached.

<Callout title="macOS">
macOS has `pipe` and `mkfifo`, and the rules for EOF and SIGPIPE are the same. `PIPE_BUF` is 512, so a portable program must not assume 4096. It has no `F_SETPIPE_SZ`, `splice`, `vmsplice` or `tee`. The kernel chooses the buffer size. Try this in bash: `yes | head -1; echo ${PIPESTATUS[0]}` prints 141.
</Callout>
