Physical memory is a cache for the pages of all programs. When it is full and a program faults, the kernel must remove a page. A **page replacement policy** chooses this victim. The wrong choice costs a disk read, which takes far longer than the fault itself. This lesson starts from [demand paging](/os/vm/page-faults-and-demand-paging).

We study a policy on a **reference string**: the list of pages that a program touches, in order. A reference to a page that is not in memory is a **fault**.

## MIN: the limit that no kernel can reach

Belady's **MIN** (1966) evicts the page whose next use is furthest in the future. An exchange argument shows that it is optimal. Suppose another policy evicts page A, and MIN evicts page B, which is used later than A. Swap the two choices. The result has the same or fewer faults, because the next use of B comes later.

MIN reads the future, so no kernel can run it. It is still useful. Run it on a recorded trace, and it tells you how much better any policy could be. The tests for this lesson check MIN against an exhaustive search of all eviction choices.

## FIFO and the anomaly

FIFO needs only a queue, but age is a poor signal. It evicts a hot page as soon as that page gets old. Worse, it can break the rule that more memory helps.

The reason is the **inclusion property**. A policy has this property if the pages in memory with $m$ frames are always a subset of the pages in memory with $m+1$ frames. Then any hit with $m$ frames is also a hit with $m+1$ frames, so the fault count cannot rise. Mattson and others (1970) call such policies **stack algorithms**.

LRU and MIN are stack algorithms. The $m$ most recently used pages are always part of the $m+1$ most recently used pages. FIFO and Clock are not stack algorithms, because their choice depends on when pages were loaded.

The inclusion property also gives a tool. One pass over a trace gives the LRU fault count for every memory size at once:

```rust
/// Mattson's stack algorithm. faults[m] is the LRU fault count with m frames.
fn lru_curve(refs: &[u32], max: usize) -> Vec<u64> {
    let mut stack: Vec<u32> = Vec::new();        // index 0 = most recently used
    let mut hits_at = vec![0u64; max];
    for &r in refs {
        if let Some(d) = stack.iter().position(|&p| p == r) {
            stack.remove(d);
            if d < max { hits_at[d] += 1; }      // a hit for every m > d
        }
        stack.insert(0, r);
    }
    let mut hits = 0;
    let mut faults = vec![refs.len() as u64; max + 1];
    for m in 1..=max { hits += hits_at[m - 1]; faults[m] -= hits; }
    faults
}
```

## LRU, and why exact LRU is too costly

**LRU** evicts the page that was used longest ago. It assumes that the recent past predicts the near future. Programs have **locality**, so this assumption is usually correct.

A database [buffer pool](/databases/storage/buffer-pools) can run LRU, because each access calls the pool. A kernel cannot do this. A program touches memory with ordinary loads and stores, and the kernel does not see them. Exact LRU would need a list update on every memory access. Only a trap on every access could give the kernel that information, and a trap costs far more than the access.

## Clock: one bit from the hardware

The hardware gives the kernel one useful bit. On x86-64, the CPU sets the **accessed bit** (A, bit 5) in a page table entry when it walks the page table for that page. On arm64, the equivalent is the access flag (AF). Hardware can set it on recent cores. Otherwise, a fault lets the kernel set it.

**Clock**, also called **second chance**, uses this bit. The frames form a ring with a hand. To find a victim:

1. Look at the frame under the hand.
2. If its accessed bit is 1, clear the bit, move the hand, and go to step 1. The page gets a second chance.
3. If its accessed bit is 0, evict this page.

A page that is in use sets its bit again before the hand returns. So the hand finds pages that were not touched in the last full turn. The bit is only one bit of history, so Clock is an approximation of LRU, and a coarse one.

## Working sets

Denning (1968) gave locality a precise form. The **working set** $W(t, \tau)$ is the set of distinct pages that a program touched in the last $\tau$ references. A program runs well if its working set is in memory.

Things to try:

1. Set $\tau$ to 200. The curve stays near 24, and it jumps at each phase change, while the old and new sets are both in the window.
2. Set $\tau$ to 10. The mean falls to 8.3 pages, so the window is too short to see the locality.
3. Set $\tau$ to 3000. The mean rises to 53.5 pages. The window now covers more than one phase. So $\tau$ must be longer than the time between uses of a hot page, and shorter than a phase.

## Thrashing

Multiprogramming helps while programs wait for I/O: another program can use the CPU. But each new program takes frames from the others. When a program has fewer frames than its working set, it faults at once and blocks. The kernel gives its frames to others, and they fault in turn. This is **thrashing**. The CPU is idle, and the paging device is saturated.

Old systems suspended whole processes to do load control. Linux does not. It reclaims until a [memory pressure](/os/memory/swapping-and-the-oom-killer) signal or the OOM killer stops the problem. On a server, the usual fix is a memory limit and fewer processes.

## What Linux does

Linux keeps lists per memory cgroup and per NUMA node, in a `struct lruvec`. The classic design has an **active** and an **inactive** list, for anonymous pages and for file pages.

- New pages usually enter the inactive list. The first touch of a file page marks it as referenced, and a second touch moves it to the active list (`folio_mark_accessed`).
- Reclaim takes pages from the tail of the inactive list (`shrink_folio_list`). It reads the accessed bits through the reverse map (`folio_referenced`). A page that was used recently goes back or is promoted.
- When the active list is too large, its tail moves to the inactive list.

A scan touches each page once, so scan pages die on the inactive list. This is the same idea as midpoint insertion in InnoDB.

**Refaults** give the kernel a signal that hardware does not. When the kernel evicts a page cache page, it leaves a small **shadow entry** in the page's slot in the cache. The entry records a clock of evictions.

If the page faults back in, the **refault distance** says how many other pages were evicted in the meantime. If that distance fits within the active list, the page would have stayed in memory with a little more space. So the kernel puts it straight on the active list (`mm/workingset.c`). The counters are in `/proc/vmstat`:

```text
workingset_refault_file   pages that came back after eviction
workingset_activate_file  of these, pages that went straight to the active list
workingset_refault_anon   the same for swapped anonymous pages
```

The **multi-generational LRU** (MGLRU, in Linux 6.1, `CONFIG_LRU_GEN`) replaces the two lists with up to four generations of pages. **Aging** walks page tables, in place of one reverse-map lookup per page, and moves pages with the accessed bit set to the newest generation. **Eviction** takes pages from the oldest generation. A page table walk is cheap when many pages in a region are used, so the CPU cost of scanning falls. `min_ttl_ms` in `/sys/kernel/mm/lru_gen/` tells the kernel to protect a working set of that age, and to use the OOM killer if it cannot.
