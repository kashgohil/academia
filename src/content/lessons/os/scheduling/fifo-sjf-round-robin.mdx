The **scheduler** is the kernel code that chooses which runnable thread gets a CPU next. This lesson uses a **job** as the unit of work: one thread that needs some CPU time. The policy has one decision to make, but two goals that conflict.

- **Turnaround time** is $T_{finish} - T_{arrival}$. It tells how long a batch job takes.
- **Response time** is $T_{first\,run} - T_{arrival}$. It tells how long a person waits for the first sign of life.

## FIFO and the convoy effect

**FIFO** (first in, first out) runs each job to completion in arrival order. It is simple and it is fair in a narrow sense. Its failure is the **convoy effect**: short jobs queue behind one long job, like cars behind a slow truck. The same effect appears at a contended lock and in a disk queue.

## Why shortest first is optimal

**SJF** (shortest job first) runs the shortest waiting job, and it does not preempt. When all jobs arrive together, SJF has the smallest possible mean turnaround. The proof is an exchange argument. It looks at two neighbors in any order.

<Steps>

Take jobs $a$ and $b$ next to each other, with $a$ first, and let $s$ be their start time. They finish at $s + a$ and $s + a + b$.

Swap them. Now they finish at $s + b$ and $s + a + b$. No other job changes its finish time, because the pair takes the same total time.

The sum of finish times changes by $b - a$. If $a > b$, the swap makes the sum smaller.

So any order with a longer job before a shorter neighbor can be improved. The only order that cannot be improved is shortest first.

</Steps>

<SjfOrderDemo />

1. Press **Swap** on a pair with the longer job first. The mean falls by the difference in length divided by 4.
2. Press **Shortest first**. The mean is 30 ms, the best of all 24 orders. **Longest first** gives 51.25 ms, the worst.

SJF has three problems. The kernel does not know burst lengths. A stream of short jobs **starves** a long job, so the long job never runs. And a short job that arrives just after a long job starts must still wait.

## Preemption and STCF

**Preemption** means that the kernel takes the CPU from a running thread. It needs a way to get control back. That way is the **timer interrupt**, which fires `CONFIG_HZ` times per second on Linux (usually 100, 250 or 1000). The handler does not switch at once. It sets the `TIF_NEED_RESCHED` flag, and the kernel calls `schedule()` at the next safe point, such as the return to user mode.

**STCF** (shortest time to completion first, also called SRPT) is SJF with preemption. On each arrival, it runs the job with the least time left. Schrage proved in 1968 that this minimizes mean turnaround on one CPU for any arrival pattern. It still needs an oracle, and it still starves long jobs.

## Round-robin and the quantum

**Round-robin** (RR) runs each job for one **quantum** (a fixed time slice), then moves it to the back of the queue. It needs no knowledge of job length, and no job starves.

For $n$ equal jobs that arrive together, the $i$-th job first runs after $i$ quanta and $i$ switches. With quantum $q$ and switch cost $c$:

$$\bar{T}_{response} = \frac{(n-1)(q+c)}{2} \qquad \text{CPU lost to switches} = \frac{c}{q+c}$$

Both terms use $q + c$, so a smaller quantum helps response only while $q$ is larger than $c$.

The switch cost here is a model input. The direct cost of a context switch is small: saved registers and a change of address space. The larger cost is often indirect, because the next job runs with cold caches and a cold TLB (the [context switching](/os/processes/context-switching) lesson measures this). So a real quantum must be much larger than the direct switch cost. Linux `SCHED_RR` uses 100 ms by default. The normal Linux scheduler uses slices of about 3 ms on a machine with 8 or more CPUs.

## I/O-bound and CPU-bound jobs

A **CPU-bound** job uses all the CPU it gets. An **I/O-bound** job runs for a short time and then blocks, for example in `read()`. While it waits, the kernel takes it off the runqueue, and `try_to_wake_up()` puts it back later.

A good policy treats each CPU burst as a small job. This gives I/O-bound jobs a fast return to the CPU, and they soon block again. CPU-bound jobs then fill the gaps. The **I/O and CPU** preset shows the result: STCF has no idle time at all.

You can see the two kinds of job from the shell. A voluntary switch means that the job blocked. An involuntary switch means that the kernel preempted it.

```sh
# Linux: GNU time, or read the counters of a live process
/usr/bin/time -v ./prog 2>&1 | grep -i 'context switches'
grep ctxt /proc/$PID/status      # voluntary_ctxt_switches, nonvoluntary_ctxt_switches

# macOS: BSD time prints the same two counters
/usr/bin/time -l ./prog
```

The core of round-robin is short. The hard part is what this loop assumes: a timer, a safe point for the switch, and a queue that is safe on many CPUs.

```rust
fn round_robin(ready: &mut VecDeque<Job>, quantum: u64, cpu: &mut Cpu) {
    while let Some(mut job) = ready.pop_front() {
        cpu.switch_to(&job);                      // costs c
        let ran = cpu.run(&job, quantum.min(job.left));
        job.left -= ran;
        ready.extend(cpu.take_arrivals());        // new arrivals go first
        if job.left == 0 { job.finish() }
        else if job.at_io_point() { job.block() }
        else { ready.push_back(job) }
    }
}
```
