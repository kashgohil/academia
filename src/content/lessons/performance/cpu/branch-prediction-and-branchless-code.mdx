A modern core fetches instructions 15 to 20 cycles before it knows the result of a branch. If the core waited, it would lose most of its speed. So it **predicts** the direction of each branch and continues on the predicted path. When the prediction is wrong, the core discards that work. Each misprediction costs about 15 to 20 cycles.

## How a 2-bit counter predicts

A simple predictor keeps a small counter for each branch. The counter has 4 states. "Taken" moves it to the right. "Not taken" moves it to the left. The two right states predict "taken".

<TwoBitStepperDemo />

1. Select **Loop of 8**. The branch is taken 7 times, then not taken once. The counter makes one mistake per loop: at the exit.
2. Select **95% taken**. Mistakes are rare.
3. Select **Alternating**. The counter cannot learn this pattern. It is wrong about half the time.
4. Select **Random**. No predictor can learn random data.

1. **Inner loop of 8**: 1-bit 25%, 2-bit 12.5%, gshare 0%.
2. **Alternating** and **Two correlated branches**: only gshare learns these. It uses the recent results of all branches.
3. **Random data**: all predictors are wrong about 50% of the time. Move the probability to 95%: the mispredictions drop to about 5%.
4. **Sorted data**: the same condition becomes almost free.

| Predictor | How it works | What it learns |
|---|---|---|
| Static | always predicts "taken" | loop branches |
| 1-bit | repeats the last result | stable branches |
| 2-bit counter | changes after two wrong results | stable branches with rare exceptions |
| gshare | uses recent branch history | patterns and branches that depend on other branches |
| TAGE, perceptron | several history lengths, or learned weights | long and irregular patterns |

Modern cores use TAGE-style or perceptron predictors. They are correct more than 95% of the time on typical code. They cannot predict random data.

## Code without branches

Look at the plot in the demo. It shows `if (x < t) sum += x` on random data:

- With a branch, the cost is about 1 cycle plus 16 × (misprediction rate).
- Without a branch, the code calculates both results and selects one (`cmov`, or a mask). The cost is always about 2 cycles.

So code without branches is faster when more than about 6% of the branches are mispredicted.

```rust
// with a branch
if x < t { sum += x; }
// without a branch: the comparison becomes a mask
sum += x & -((x < t) as i32);
// or ask the compiler for a conditional move
sum += std::hint::select_unpredictable(x < t, x, 0);
```

In C and C++, use `__builtin_unpredictable` (Clang) or `__builtin_expect_with_probability` (GCC). Compilers often make conditional moves without help. Look at the assembly before you write bit tricks.

Do not remove a branch that is predictable. A predictable branch costs almost nothing. Do not remove a branch if one side is expensive, because code without branches always runs both sides. You can also sort or partition the data, so the branch becomes predictable.
