A pipelined, out-of-order core fetches instructions 15–20 cycles before it knows the outcome of the branches among them. Waiting would waste most of its capacity, so it **predicts** each branch and runs ahead speculatively. When the guess is wrong, everything after the branch is thrown away. That costs about 15–20 cycles per misprediction: the "bad speculation" category from the hardware-counters lesson.

1. **Inner loop of 8**: 1-bit 25%, 2-bit 12.5%, gshare 0%.
2. **Alternating** and **correlated branches**: per-branch counters fail; gshare learns them from the recent history of all branches.
3. **Random data** at p = 50%: every predictor is at a coin flip. Slide p up: at 95% taken, mispredicts fall to about 5%.
4. **Sorted data**: the same condition is perfectly predictable. That's the famous "why is processing a sorted array faster" result.

## Predictors

| Design | Idea | Learns |
|---|---|---|
| Static | always taken (loops) or backward-taken / forward-not-taken | loop back-edges |
| 1-bit | repeat last outcome | stable branches |
| 2-bit saturating counter | flip only after two misses in a row | stable branches with rare exceptions |
| gshare / two-level | index counters by recent global branch history ⊕ PC | patterns and correlations between branches |
| TAGE, perceptron | several history lengths, tagged tables or learned weights | long, irregular patterns |

Modern cores use TAGE-style or perceptron-based designs (often both, with a loop predictor added). They predict typical code with over 95% accuracy. What they can't predict is data: a branch on random input is a coin flip for any predictor.

## Branchless code

The plot shows the trade-off for `if (x < t) sum += x` on random data. A branch costs about 1 cycle plus 16 × (mispredict rate). A branchless version (compute both sides and select with `cmov`, or with a mask) costs a fixed 2 cycles. Branchless wins when mispredicts exceed about 6%: data closer to 50/50 than about 94/6.

```rust
// branchy
if x < t { sum += x; }
// branchless: the comparison becomes a mask
sum += x & -((x < t) as i32);
// or ask the compiler for a conditional move:
sum += std::hint::select_unpredictable(x < t, x, 0);
```

C and C++ have `__builtin_unpredictable` (Clang) and `__builtin_expect_with_probability` (GCC) as hints. Compilers already turn simple ternaries into `cmov` when they judge it profitable. Check the assembly before hand-rolling bit tricks.

When *not* to go branchless: when the branch is predictable (then it's nearly free, and branchless always pays both sides), or when one side is expensive (computing it unconditionally costs more than the occasional miss). Other options: sort or partition the data so the branch becomes predictable, or vectorize (SIMD lesson), which uses masks anyway.
