An out-of-order core looks at hundreds of upcoming instructions. It starts each instruction as soon as its inputs are ready. It can start several instructions in each cycle. Two limits control the speed:

- **Throughput**: how many instructions of one type can start in each cycle. A typical core can start 2 floating-point adds per cycle.
- **Latency**: how long one instruction takes before its result is ready. A floating-point add takes about 4 cycles. An instruction that needs this result must wait.

A loop runs at the slower of the two limits. Many simple loops are limited by latency.

1. With **1** accumulator, the schedule is a staircase. One add starts every 4 cycles.
2. With **2**, **4** and **8** accumulators, the chains overlap. The cost per element drops from 4 to 2, 1 and 0.5 cycles.
3. With **16** accumulators, there is no more gain. The limit is now 2 adds per cycle.

## The rule

The number of independent chains that you need is:

$$\text{chains} = \text{latency} \times \text{throughput} = 4 \times 2 = 8$$

This is Little's law inside the core. To keep 2 adds per cycle running for 4 cycles each, 8 adds must be in progress at the same time.

## Where this applies

- **Reductions** (sums, dot products, minimum, hashes): use several accumulators and combine them at the end. For floating-point numbers, this changes the rounding. So the compiler does not do it without `-ffast-math`.
- **Polynomials**: Horner's method is one long chain. Estrin's method calculates pairs in parallel.
- **Linked structures**: each load in a pointer chase needs the previous load. Walk several independent lists at the same time.
- **Loop unrolling** helps because it lets you use several accumulators. Unrolling with one accumulator does not shorten the chain.

```zig
var s0: f32 = 0; var s1: f32 = 0; var s2: f32 = 0; var s3: f32 = 0;
var i: usize = 0;
while (i + 4 <= a.len) : (i += 4) { s0 += a[i]; s1 += a[i + 1]; s2 += a[i + 2]; s3 += a[i + 3]; }
var s = (s0 + s1) + (s2 + s3);
while (i < a.len) : (i += 1) s += a[i];
```

Tools such as llvm-mca and uiCA calculate the schedule of a loop for a given CPU. The tables of uops.info and Agner Fog list the latency and throughput of each instruction.
