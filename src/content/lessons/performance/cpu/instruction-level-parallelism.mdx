An out-of-order core looks at a window of hundreds of upcoming instructions and starts any whose inputs are ready, several per cycle. Its speed is therefore bounded by two things:

- **Throughput**: how many instructions of each kind can start per cycle (ports). Typically 2 FP adds per cycle.
- **Latency along dependency chains**: an instruction can't start until the instructions it depends on have finished. An FP add takes about 4 cycles.

A loop runs at the slower of the two limits. Most simple loops are limited by latency without anyone noticing.

1. With **1 accumulator** the schedule is a staircase: one add every 4 cycles, loads finished long before they're needed.
2. With **2, 4, 8** accumulators the chains overlap, and cycles per element fall 4 → 2 → 1 → 0.5.
3. With **16**: no further gain. The limit is now throughput, 2 adds per cycle.

## The rule

The number of independent chains needed to saturate a unit is

$$\text{chains} = \text{latency} \times \text{throughput} = 4 \times 2 = 8.$$

That's Little's law (the queueing lesson) applied inside the core: to keep 2 adds per cycle in flight for 4 cycles each, you need 8 in progress at once.

## Where this shows up

- **Reductions** (sums, dot products, min/max, hashes): split into several accumulators and combine at the end. For floats this changes rounding, which is why compilers won't do it for you without `-ffast-math` / `-fassociative-math` (the auto-vectorization lesson).
- **Polynomials**: Horner's rule is one long chain. Estrin's scheme evaluates pairs in parallel.
- **Linked structures**: pointer chasing is a chain of loads with about 5 cycles of latency even from L1 (90 ns from DRAM). Walking several independent lists at once overlaps them.
- **Loop unrolling** helps mainly by allowing multiple accumulators and cutting per-iteration overhead. Unrolling a single-accumulator loop does nothing for the dependency chain.

```zig
var s0: f32 = 0; var s1: f32 = 0; var s2: f32 = 0; var s3: f32 = 0;
var i: usize = 0;
while (i + 4 <= a.len) : (i += 4) { s0 += a[i]; s1 += a[i + 1]; s2 += a[i + 2]; s3 += a[i + 3]; }
var s = (s0 + s1) + (s2 + s3);
while (i < a.len) : (i += 1) s += a[i]; // tail
```

Tools: uiCA and llvm-mca model the schedule of a loop body on a specific microarchitecture and report whether it is latency- or throughput-bound. Agner Fog's instruction tables and uops.info list latency and throughput per instruction.
