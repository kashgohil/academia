**SIMD** (single instruction, multiple data) registers hold several values. A 128-bit SSE or NEON register holds 4 floats. A 256-bit AVX2 register holds 8. An AVX-512 register holds 16. One instruction works on all the values, which are called **lanes**.

## One at a time, or a vector at a time

<LaneRaceDemo />

1. Watch the two rows. The scalar row adds one pair in each step. The SIMD row adds a full vector in each step.
2. Change the lanes to **16**. The SIMD row finishes in 2 steps.
3. Look at the tree below the rows. At the end, the lanes of one vector must be added together. This takes $\log_2(\text{lanes})$ steps.

1. Use **1** vector accumulator. AVX2 is only about 8 times faster than scalar code. There is still one chain.
2. Use **8** vector accumulators. Now both limits are used.
3. Look at the mask table. It shows how `if (x > 0) sum += x` works without a branch. A compare makes a mask for all lanes. The mask selects the values to add.

## How to write it

```rust
use std::arch::x86_64::*;
#[target_feature(enable = "avx2")]
unsafe fn sum(a: &[f32]) -> f32 {
    let mut acc = [_mm256_setzero_ps(); 4];
    let chunks = a.chunks_exact(32);
    let tail = chunks.remainder();
    for c in chunks {
        for k in 0..4 { acc[k] = _mm256_add_ps(acc[k], _mm256_loadu_ps(c.as_ptr().add(8 * k))); }
    }
    let v = _mm256_add_ps(_mm256_add_ps(acc[0], acc[1]), _mm256_add_ps(acc[2], acc[3]));
    let mut lanes = [0f32; 8];
    _mm256_storeu_ps(lanes.as_mut_ptr(), v);
    lanes.iter().sum::<f32>() + tail.iter().sum::<f32>()
}
```

```zig
fn sum(a: []const f32) f32 {
    const V = @Vector(8, f32);
    var acc: V = @splat(0);
    var i: usize = 0;
    while (i + 8 <= a.len) : (i += 8) acc += a[i..][0..8].*;
    var s = @reduce(.Add, acc);
    while (i < a.len) : (i += 1) s += a[i];
    return s;
}
```

You have three options:

- **Vector types**: Zig `@Vector`, Odin `#simd[8]f32`, C++26 `std::simd`, Rust `std::simd` (nightly) or the `wide` crate.
- **Intrinsics**: `immintrin.h`, `arm_neon.h`, Rust `std::arch`.
- **Libraries**: simdjson, Highway, xsimd.

## Common problems

<Steps>
<div><b>Tails</b>: the number of items is often not a multiple of the lane count. Process the rest with a scalar loop or with masked loads.</div>
<div><b>Horizontal sums</b>: add the lanes only once, at the end. Never do it inside the loop.</div>
<div><b>Branches become masks</b>: the code calculates both sides. This is cheap for simple conditions, but expensive if one side is large.</div>
<div><b>Data layout</b>: SIMD needs each field in its own array (see the SoA lesson). Loads from scattered addresses are slow.</div>
<div><b>CPU support</b>: not every CPU has AVX2 or AVX-512. Check at runtime (`is_x86_feature_detected!`, `__builtin_cpu_supports`), or compile several versions.</div>
</Steps>

<Callout kind="warn" title="Wider is not always faster">
Some older Intel server CPUs reduced their clock speed during heavy AVX-512 use. Loops that wait for memory get nothing from wider vectors. Measure before you choose the widest instructions.
</Callout>
