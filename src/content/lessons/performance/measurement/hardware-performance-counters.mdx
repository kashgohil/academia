Timing tells you *that* code is slow. The CPU can tell you *why*. Every modern core has **performance monitoring counters** that count events (cycles, instructions retired, cache misses, branch mispredictions, and hundreds more) with almost no overhead. `perf stat` reads them for a whole run:

```
$ perf stat -e cycles,instructions,branch-misses,cache-misses ./app
```

The first number to read is **IPC** (instructions per cycle). A modern core can retire 4–6 instructions per cycle. IPC below 1 means it spends most cycles waiting.

## Top-down analysis

Intel's **top-down microarchitecture analysis** (Yasin, 2014) accounts for every pipeline *slot*: the core's width × cycles. Each slot is classified as one of:

| Category | Meaning | Typical fixes |
|---|---|---|
| **Retiring** | useful work | fewer instructions: better algorithm, SIMD |
| **Bad speculation** | work thrown away after mispredicted branches | predictable branches, branchless code, sorting or partitioning data |
| **Frontend bound** | the core couldn't fetch or decode instructions fast enough | smaller hot code, fewer i-cache/iTLB misses, PGO and LTO |
| **Backend: memory** | waiting on loads (cache and DRAM misses) | locality, prefetching, smaller data |
| **Backend: core** | execution units or dependency chains | break dependency chains, more ILP |

Start at the top level, then drill into the dominant category. `perf stat -M TopdownL1` (newer kernels, Intel and some AMD), `toplev` from pmu-tools, VTune and AMD uProf all report it.

## Practicalities

- Counting (`perf stat`) is cheap and exact. Sampling on an event (`perf record -e cache-misses`) attributes events to code, with skid (see Profilers).
- There are only a few hardware counters (4–8 general-purpose per core). Ask for more events than that and `perf` time-multiplexes them, scaling the counts: you'll see percentages in brackets.
- Virtual machines and containers often hide or virtualize counters. Measure on bare metal when you can.
- `perf c2c` (false sharing), `perf mem` (load latency) and `perf stat -e L1-dcache-load-misses,LLC-load-misses` connect this lesson to the cache and coherence modules.
