Big-O notation counts operations. But real code is often limited by its **memory access pattern**. Some accesses are predictable: the prefetcher loads the data early, and many misses overlap. Other accesses are unpredictable: each miss stops the core for the full latency. Two structures with the same big-O can differ by 40 times.

## See the difference

<PointerWalkDemo />

1. Turn off **Nodes scattered in memory**. The walk moves through memory in order. Each cache line holds 4 nodes, so only 1 node in 4 causes a miss.
2. Turn the option on. The walk jumps through memory. Almost every node causes a miss.

1. Compare the three walks at 262,144 elements: the array takes 0.3 ns, the list in order 1.1 ns, and the scattered list 13 ns.
2. Select **4,096** elements. All the data fits in the L2 cache. The scattered list now costs only about 3.6 ns.
3. Compare the hash tables. Chaining needs two misses per lookup: the bucket, then the node. Open addressing usually needs one.

## Loop order and tiling

A matrix multiply visits every point (i, j, k) of a cube. The loop order decides the path through the cube. The path decides which elements stay in the cache.

<IterationSpaceDemo />

1. Select **i, j, k**. The inner loop moves along k. Each step needs a new row of B, so B is rarely in the cache.
2. Select **i, k, j**. The inner loop moves along j. A, B and C are all read along rows. There are fewer misses.
3. Select **tiled 4×4**. The loop works on small blocks that fit in the cache. It has the fewest misses.
4. Drag the cube to turn it.

## Common choices

| Instead of | Use | Why |
|---|---|---|
| Linked list | Array or vector | contiguous memory, one access per element |
| Hash table with chaining | Open addressing (Swiss tables) | the key and value are in the table |
| Binary tree with small nodes | B-tree, or a sorted vector for read-mostly data | one miss gives many keys |
| Vector of pointers to objects | Vector of objects | one dependent miss less per element |
| Nodes allocated one at a time | Arena or pool allocation | the nodes are next to each other |

To find memory problems, run `perf stat -e cycles,instructions,L1-dcache-load-misses,LLC-load-misses`. A low IPC and many misses mean that the code waits for memory.
