The same table of entities can be stored two ways:

```rust
struct Particle { x: f32, y: f32, z: f32, vx: f32, vy: f32, vz: f32, mass: f32, /* … */ }
let aos: Vec<Particle>;                         // array of structs: fields side by side

struct Particles { x: Vec<f32>, y: Vec<f32>, z: Vec<f32>, vx: Vec<f32>, /* … */ }
let soa: Particles;                             // struct of arrays: one array per field
```

A cache line is 64 bytes. With AoS, reading one 4-byte field from each entity still loads every entity's whole struct. With SoA, a loop pulls in only the arrays it names.

1. Move **fields read** from 1 to 16 with 16 fields per entity. AoS costs nearly the same whatever you read (it always moves whole lines); SoA cost grows with each field you read, and reaches AoS when you read everything.
2. Set fields per entity to **4**: a struct is 16 bytes and AoS wastes far less. SoA's advantage depends on how wide the struct is relative to what the loop uses.
3. Watch **AoSoA** (array of structs of arrays): blocks of 8 entities, each field stored as 8 adjacent values. It behaves like SoA for bandwidth and keeps one entity's fields within a small region.

## Choosing

| Layout | Good for | Watch out for |
|---|---|---|
| AoS | loops that use most fields of each item; random access to whole items | wasted bandwidth when loops read few fields |
| SoA | loops over a few fields of many items; SIMD (`x[i..i+8]` is one vector load) | many streams at once can conflict in cache sets; random access to one item touches many lines |
| AoSoA | SIMD-width blocks (e.g. 8 for AVX2 f32) with locality per block | awkward indexing; usually generated by a library |
| Hot/cold split | the common case: a hot struct for the inner loop plus a cold struct by index | keeping the two in sync |

<Callout title="A pitfall SoA can hit">
If each array's size is a large power of two, the arrays start at addresses that map to the same cache sets, and reading many of them at once evicts lines from each other. Allocators and careful code stagger array starts. The demo staggers them by one line; without that, its 16-field SoA case runs slower than AoS.
</Callout>

Tooling exists: Zig's `std.MultiArrayList(T)` turns a struct into SoA storage automatically; Rust has `soa_derive`; ISPC and many ECS libraries generate AoSoA. In C++, most people write the parallel arrays by hand, or use a component framework.
