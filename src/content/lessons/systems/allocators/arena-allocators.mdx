A bump allocator over a fixed buffer runs out. An **arena** fixes that by bump-allocating inside *chunks* it obtains from a backing allocator (the OS, `malloc`, or a parent arena). When the current chunk can't fit a request, the arena abandons its tail and opens a new chunk. Freeing the arena returns every chunk at once. Zig's `std.heap.ArenaAllocator`, Odin's `mem.Arena` and its `context.temp_allocator`, Rust's `bumpalo`, and C++'s `std::pmr::monotonic_buffer_resource` all work like this.

Things to try:

1. Run **3 × 100 B** with 128, 256 and 512 B chunks. Small chunks waste more on headers and abandoned tails; big chunks hold memory you may never use.
2. Request **500 B** with 256 B chunks. Oversized requests get a dedicated chunk rounded up to whole chunk sizes.
3. Run **Frame loop**: each frame begins a scope, allocates temporaries and ends the scope. The same memory is reused every frame with zero bookkeeping.
4. Free individual blocks: they turn grey. An arena only gives memory back when it is reset or a scope ends.

## The cost model

For a typical allocation size $s$ and chunk size $C$:

- **Header overhead** is $h/C$ per chunk.
- **Abandoned tails** average about $s/2$ per chunk, so the fraction wasted is roughly $\frac{s}{2C}$. Chunks should be large compared with typical allocations.
- **Backing calls** happen once per chunk. Many arenas *grow* chunk sizes geometrically, so a long-lived arena makes $O(\log n)$ backing calls.

Allocation stays a bump in the common case. The arena's real cost is its **high-water mark**: it holds its peak usage until reset.

## Designing with lifetimes

The arena's power is architectural. Instead of tracking each object, you tie groups of objects to an event:

| Lifetime | Arena | Reset when |
|---|---|---|
| Frame (games, UIs) | per-frame scratch, often double-buffered | frame ends |
| Request (servers) | per-request arena | response sent |
| Pass (compilers) | per-phase arena: tokens, AST, IR | phase output is consumed |
| Call (any code) | scratch scope with mark/restore | function returns |

```zig
var arena = std.heap.ArenaAllocator.init(std.heap.page_allocator);
defer arena.deinit(); // frees every chunk at once
const a = arena.allocator();
const tokens = try lex(a, source); // no individual frees anywhere
```

```odin
process :: proc(input: string) {
    defer free_all(context.temp_allocator)
    parts := strings.split(input, ",", context.temp_allocator)
    // ...
}
```

<Callout kind="warn" title="The failure mode: silent dangling pointers">
After a reset, old pointers still point at valid, mapped memory, which is now being reused. Reading through them doesn't crash; it returns someone else's data. Never let an arena pointer escape into something that outlives the arena. Debug builds can poison memory on reset (fill it with a pattern such as `0xAA`) to make such bugs visible.
</Callout>
