A **bump allocator** owns a buffer and one integer, `top`. The integer `top` is the offset of the first free byte. To allocate, the allocator rounds `top` up to the requested alignment. Then it checks the end of the buffer and moves `top` forward. That is the full fast path: a few instructions, no metadata and no search.

**Alignment** is a rule that a value must start at an address that is a multiple of a number. Usually that number is the size of the value. Hardware requires aligned access, or runs it faster.

Compilers use bump allocators for syntax tree nodes. Games use them for data that lives for one frame. Zig's `FixedBufferAllocator`, Odin's temp allocator and Rust's `bumpalo` use one inside.

## Alignment arithmetic

Alignments are powers of two. Because of this, rounding up is a bit operation:

<Steps>
<div>We want the smallest multiple of $a$ that is $\ge x$. Add $a-1$ to $x$. This moves $x$ past the next multiple, unless $x$ is already on a multiple.</div>
<div>For $a = 2^k$, rounding down to a multiple of $a$ clears the low $k$ bits. That is an AND with $\lnot(a-1)$.</div>
<div>Put the two steps together: $\text{align\_up}(x, a) = (x + a - 1)\ \&\ \lnot(a - 1)$. For $x = 17$ and $a = 8$: $(24)\ \&\ \lnot 7 = 24$.</div>
<div>The padding is $\text{align\_up}(x, a) - x$. It is between $0$ and $a - 1$ bytes.</div>
</Steps>

```zig
const Bump = struct {
    buf: []u8,
    top: usize = 0,

    fn alloc(self: *Bump, n: usize, alignment: usize) ?[*]u8 {
        const start = std.mem.alignForward(usize, self.top, alignment);
        if (start + n > self.buf.len) return null;
        self.top = start + n;
        return self.buf.ptr + start;
    }
};
```

## Struct layout is the same problem

A compiler that lays out a struct does the work of a bump allocator over the fields. The demo shows the same fields in two orders.

<StructLayoutDemo />

Things to try:

1. Click **char, double, char, double**. Declaration order needs 32 bytes. Sorted order needs 24 bytes: 18 bytes of data and 6 bytes of tail padding.
2. Click **double, char**. The struct is 16 bytes, not 9. The tail padding keeps the next element of an array aligned.
3. Click **char, int, char, short, ptr**. Declaration order needs 24 bytes. Sorted order needs 16 bytes.
4. Build your own struct with the **Add a field** buttons. Sorted order is never larger than declaration order.

Languages treat field order in different ways:

- **C, C++ and Zig `extern struct`** keep declaration order. So the field order decides the padding. Sort the fields by decreasing alignment to get the least padding.
- **Rust** (default `repr(Rust)`) and **Zig** (plain `struct`) can change the field order to make less padding. Use `#[repr(C)]` or `extern struct` when the layout must not change, for example for FFI or file formats.
- **Odin** keeps declaration order by default. The `#packed` attribute removes all padding, but then the fields can be unaligned.

The compiler rounds the total size up to the alignment of the struct. The alignment of the struct is the largest alignment of its fields.

## What "free" means here

A bump allocator can get memory back only at the top. In practice it supports three operations:

- **LIFO free**: LIFO means "last in, first out". A free of the newest allocation moves `top` back. This makes the allocator a stack allocator.
- **Reset**: free all allocations in one step.
- **Mark and restore**: save `top`, do temporary work, then put `top` back to the saved value. This is a scoped stack. The **Begin scope** and **End scope** buttons do this.

All other frees do nothing until the next reset. This is not a defect. It is the design. **Bump allocation works when lifetimes are grouped**, so that many objects become unused at the same time. When they do not, use a pool or a general-purpose allocator.

| Property | Bump |
|---|---|
| alloc | $O(1)$, about 3 instructions |
| free | $O(1)$ at the top; otherwise it does nothing |
| metadata per allocation | none |
| locality | very good: allocations are next to each other, in program order |
| fragmentation | none, until you need individual frees |
