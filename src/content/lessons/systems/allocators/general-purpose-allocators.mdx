Modern general-purpose allocators (mimalloc, jemalloc, tcmalloc, and glibc's small-object paths) all combine the ideas from this module:

1. Round small requests up to a **size class**.
2. Serve each class from **pages dedicated to that class**, like slabs but without per-type caches.
3. Send **large** requests to runs of whole pages, which come from something buddy-like or from the OS directly.
4. Keep metadata **out of band**: the page number of an address (`addr >> page_shift`) indexes a page table that knows the class. `free` needs no header and no search.
5. Give every thread its own heap or cache, so the fast path takes no lock.

The demo implements steps 1–4 in a 16 KiB heap with 1 KiB pages.

Things to try:

1. Run **alloc(33)** under both class settings: 64 B vs 48 B.
2. **Churn** under each setting and compare the *slack / live* readout with how many pages are touched. Fine classes cut slack but open more pages.
3. Run **alloc(3000)**: it takes three whole pages, the large-object path.
4. Free everything in a page and watch it return to the free pool, ready to serve any class.

## Choosing size classes

The usual design is roughly **geometric spacing with a few steps per doubling**. jemalloc, for example, uses 4 classes per doubling, so worst-case rounding waste is about 20%. Spacing is a three-way trade-off:

| Finer classes | Coarser classes |
|---|---|
| less rounding waste per object | more rounding waste |
| more partially filled pages | fewer, fuller pages |
| more metadata and per-class caches | less |

## Threads

A single global lock would serialize every `malloc`. The fixes, in roughly historical order:

- **Arenas per thread or per CPU** (glibc, jemalloc): a thread allocates from "its" arena, which reduces contention.
- **Thread caches** (tcmalloc, jemalloc's tcache, glibc's tcache): small per-thread stacks of free objects per class, so the common path needs no synchronization.
- **Free-list sharding** (mimalloc): each *page* has its own free list, plus a separate atomic list for objects freed by *other* threads. The owner collects those later in bulk. This keeps locality and avoids most atomics.

Cross-thread frees (allocate on one thread, free on another) are the hard case, as in producer/consumer queues. They are also where allocator choice shows up in benchmarks.

## In your languages

- **C / C++**: `malloc` is glibc's ptmalloc by default on Linux. Swap it with `LD_PRELOAD=libmimalloc.so` or by linking jemalloc.
- **Rust**: uses the system allocator. Replace it with `#[global_allocator] static A: mimalloc::MiMalloc = mimalloc::MiMalloc;`.
- **Zig**: no hidden allocations. You pass an allocator explicitly. The standard library includes a page allocator, `DebugAllocator` (formerly `GeneralPurposeAllocator`, which detects leaks and double frees) and `smp_allocator` for release builds. You can also use `std.heap.c_allocator`.
- **Odin**: `context.allocator` defaults to a heap allocator over the platform's `malloc`. Override it per scope by assigning to `context.allocator`.
- **Go**: a tcmalloc-derived allocator with per-P caches (`mcache`), size classes and spans, integrated with the garbage collector.
