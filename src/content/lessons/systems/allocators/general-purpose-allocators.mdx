A **general-purpose allocator** serves any size, at any time, from any thread. Modern ones, such as mimalloc, jemalloc, tcmalloc and the small-object paths of glibc, all combine the ideas of this module:

1. Round each small request up to a **size class**: one of a fixed list of block sizes.
2. Serve each class from **pages for that class only**. These are like slabs, but there is no cache per type.
3. Send **large** requests to runs of whole pages. These come from a buddy-like page allocator or from the operating system (OS).
4. Keep the metadata **out of band**, in a table outside the blocks. The page number of an address (`addr >> page_shift`) selects a table entry that knows the class. So `free` needs no header and no search.
5. Give each thread its own heap or cache, so the fast path takes no lock.

The first demo does steps 1 to 4 in a 16 KiB heap with 1 KiB pages.

## Choose the size classes

Most allocators space their classes geometrically, with a few classes in each doubling of size. jemalloc, for example, uses 4 classes in each doubling. The spacing controls the worst-case and the average rounding waste.

<ClassSpacingDemo />

Things to try:

1. Select **1 (powers of two)**. The worst case is just under 50% (49.95%, at 1025 B). The average waste is 25%.
2. Select **4 (jemalloc)**. The worst case drops to 19.92%, and the average drops to 7.9%. There are now 16 classes between 129 B and 2 KiB, instead of 4.
3. Select **8**. The worst case is 11.02%, but there are 32 classes. Each class needs its own pages and caches.
4. Move the request size. The waste is largest just above a class boundary. It drops to zero at the next class.

The spacing is a three-way trade-off:

| Finer classes | Coarser classes |
|---|---|
| less rounding waste per object | more rounding waste |
| more pages that are partly full | fewer pages, and fuller ones |
| more metadata and more caches per class | less |

## Threads

One global lock would make each `malloc` wait for the others. These are the fixes, in rough historical order:

- **Arenas per thread or per CPU** (glibc, jemalloc). A thread allocates from "its" arena. This reduces contention for the lock.
- **Thread caches** (tcmalloc, the tcache of jemalloc, the tcache of glibc). Each thread keeps a small stack of free objects for each class. The common path needs no synchronization.
- **Free-list sharding** (mimalloc). Each page has its own free list, plus a separate atomic list for objects that *other* threads free. The owner thread collects these objects later, in one batch. This keeps locality and prevents most atomic operations.

The next demo models a tcmalloc-style allocator with four levels. A **thread cache** holds free objects for one thread. A **central free list** holds free objects for all threads, behind a lock. The **page heap** holds free pages. When it is empty, it asks the OS for 1 MiB more.

The model gives each level a cost: 1, 10, 100 and 1000 units. Each level is roughly ten times slower than the level above it. Real costs depend on the machine and on the allocator. In the model, requests above 32 KiB are large, and they go to the page heap directly.

Frees from another thread are the difficult case. Producer and consumer queues do this all the time. Benchmarks of this pattern often show the largest differences between allocators.

## In your languages

- **C and C++**: on Linux, `malloc` is the ptmalloc allocator of glibc by default. To change it, use `LD_PRELOAD=libmimalloc.so` or link with jemalloc.
- **Rust**: Rust uses the system allocator. Replace it with `#[global_allocator] static A: mimalloc::MiMalloc = mimalloc::MiMalloc;`.
- **Zig**: Zig has no hidden allocations. You pass an allocator explicitly. The standard library has a page allocator and `DebugAllocator`, which finds leaks and double frees. It also has `smp_allocator` for release builds, and `std.heap.c_allocator`.
- **Odin**: `context.allocator` is a heap allocator over the `malloc` of the platform by default. To change it for one scope, assign a new value to `context.allocator`.
- **Go**: Go has an allocator derived from tcmalloc, with a cache per P (`mcache`), size classes and spans. It works together with the garbage collector.

`DebugAllocator` was earlier called `GeneralPurposeAllocator`.
