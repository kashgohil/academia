Kernels allocate the same few object types (inodes, dentries, socket buffers, task structs) millions of times. Jeff Bonwick's **slab allocator** (SunOS, 1994; the basis of Linux's SLAB and today's SLUB) gives each type or size its own **cache**. A cache owns **slabs**: pages carved into equal-sized objects, plus a small descriptor. Allocation pops a free object from a partially used slab. When a slab becomes completely empty, its page can go back to the page allocator, which is usually a buddy allocator.

Things to try:

1. Run **alloc + free one 40 B object × 10**, with and without *Keep one empty slab per cache*.
2. Run **Mixed objects**: 15 objects of 7 sizes map to 5 caches (16, 32, 64, 128, 256 B) and occupy 5 pages, most of them nearly empty. Per-size caches waste memory when a size has only a few live objects.
3. Fill one cache until a second slab opens, then free objects from the first. The cache keeps allocating into partial slabs before touching empty ones, which keeps memory dense.
4. Look at the slack at the end of each 512 B page: 480 usable bytes split into 128 B objects leaves 96 B unused. Real implementations choose slab sizes (sometimes several pages) to keep this small.

## What a slab allocator adds

- **Exact-fit caches.** A cache for a 192-byte struct wastes nothing per object, unlike power-of-two rounding.
- **Partial-first allocation.** Filling partial slabs before using empty ones lets empty slabs accumulate, so they can be returned.
- **Object caching.** Bonwick's original insight was that constructing an object (initializing locks, lists, reference counts) often costs more than allocating it. Freed objects stay in their constructed state, so reallocation skips initialization.
- **Cache coloring.** Different slabs start their objects at slightly different offsets, so the same field in objects from different slabs doesn't always map to the same CPU cache set (see Computer Architecture → Caches).
- **Per-CPU caches.** SLUB and magazine-based designs keep small per-CPU stacks of free objects, so the common path takes no lock.

On Linux, `/proc/slabinfo` and `slabtop` list every cache with its object size, objects per slab and active counts.
