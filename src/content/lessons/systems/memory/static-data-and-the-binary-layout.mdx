A global variable exists before `main` starts and until the process exits. This is **static storage duration**. The compiler decides where each global goes, and the program file stores what the loader needs to set it up. The choice depends on two questions: can the bytes change, and are they all zero?

The compiler puts each kind of data in its own **section**, a named range of bytes in an object file. The linker joins equal sections from all object files. The loader then maps them into memory with the right access rights. This lesson stays at the level of "what goes where and why". The [linking module](/systems/linking/object-files-and-elf) shows the ELF records themselves.

3. Select **Rust**. An immutable `static` of zeros goes to `.rodata`, not `.bss`, so its zeros take file space.
4. Select **Zig**. The same `undefined` array goes to `.data` in a Debug build and to `.bss` in ReleaseSmall.
5. Select **Go**. Its sections split by one more question: does the data hold pointers?

## The four sections

| Section | Holds | Rights at run time | In the file |
|---|---|---|---|
| `.text` | machine code | read, execute | yes |
| `.rodata` | constants, string literals, jump tables | read | yes |
| `.data` | writable globals with a nonzero initializer | read, write | yes |
| `.bss` | writable globals that start as zero | read, write | no: only the size |

The linker puts sections with the same rights into one **segment**, a `PT_LOAD` entry in the program header. A segment has two sizes: `p_filesz`, the bytes in the file, and `p_memsz`, the bytes in memory. For the writable segment, `p_memsz` is larger. The loader maps the file bytes and fills the rest with zero pages. The kernel provides those pages only when the program first touches them, as [demand paging](/os/vm/page-faults-and-demand-paging) explains.

So `.bss` is free in the file and cheap at startup. A 1 MiB zero buffer costs 1 MiB of address space, but physical memory only for the pages that the program writes. The C standard requires zero for a static object without an initializer (N1570 6.7.9p10). So the compiler can use `.bss` for both an omitted initializer and an explicit `= 0`. GCC has `-fno-zero-initialized-in-bss` to turn this off.

Two old C details still matter. A file-scope `int x;` without `extern` is a **tentative definition**. Old compilers put it in a COMMON block, and the linker merged equal names from different files. GCC 10 made `-fno-common` the default, and Clang 11 followed. Now two files that both define `int x;` fail to link, which is correct.

Each language adds its own rules:

- **Rust.** An immutable `static` cannot change, so rustc 1.96 puts it in `.rodata`, even when it is all zero. A `static mut`, or a type with interior mutability such as `AtomicU32`, goes to `.data` or `.bss`. A `static NAME: &str` goes to `.data.rel.ro`: the dynamic loader writes the address once, and then the page becomes read-only.
- **Zig.** A container-level `var` with `undefined` has no value. In Debug mode Zig fills undefined memory with 0xAA bytes, so the array is stored in `.data`. In the release modes that we tried with zig 0.17.1, it went to `.bss`.
- **Go.** The linker uses `.noptrdata` and `.noptrbss` for globals without pointers, and `.data` and `.bss` for globals with pointers. The garbage collector scans only the second pair as roots. A `string` holds a pointer, so a string global lands in `.data`.

## String literals and static locals

A string literal such as `"hello"` is an array with static storage duration. The C standard says that a program that modifies it has undefined behavior (N1570 6.4.5p7). The compiler puts it in a read-only section, `.rodata.str1.1` in an object file from clang. The linker can merge equal strings across files, because no program may write them.

`char *s = "hello";` makes a pointer to that read-only array. `char a[] = "hello";` makes a new array and copies 6 bytes into it. Only the second one is yours to change.

A `static` local is a global with a hidden name. Its symbol is `count.calls` in the clang object file. It keeps its value between calls, and it is shared by all threads. A function with a static local is therefore not reentrant, unless the variable is thread-local or protected.

## Initialization order

Some globals need code to compute their first value. C forbids this: every initializer of a static object must be a constant expression (N1570 6.7.9p4). So a C program never runs code before `main` for its own globals. The other languages differ.

Things to try:

1. Keep **C++** with both boxes checked. The order works, and `cache` gets 6,144 bytes.
2. Clear **Link logger.o before app.o**. `config` runs before the constructor of `logger` and reads 0. We saw this with Apple clang 21: the program printed 0 with one link order and 6 with the other.
3. Turn the link order back on and clear **declare config before cache**. Now the error is inside one file.
4. Select **Go** and change the declaration order. Go sorts by dependency, so the result is always 6,144.
5. Select **Rust LazyLock** and **Zig**. Rust runs nothing before `main`. Zig computes the values at compile time.

**C++.** Dynamic initialization in one file follows declaration order. Across files, the order is not specified: the standard calls it "indeterminately sequenced" ([basic.start.dynamic]). In practice the link order decides. A global that reads a global from another file can see it before its constructor runs. This is the **static initialization order fiasco**.

There are two standard fixes. A function-local static is built on first use, and C++11 makes that thread-safe. C++20 `constinit` forces a compile-time initializer, or the code does not compile.

```cpp
Logger& logger() {
    static Logger instance; // built on the first call, once
    return instance;
}
```

**Go.** The language specification defines the order. Package-level variables initialize "stepwise, with each step selecting the variable earliest in declaration order which has no dependencies on uninitialized variables". Then the `init` functions run, then `main`. A dependency cycle is a compile error, for example `initialization cycle for a` with Go 1.25.

**Rust.** A `static` initializer must be a constant expression. With rustc 1.96, `static PREFIX: String = String::from("[app] ");` fails with E0015, and the error suggests `std::sync::LazyLock`. `LazyLock` (stable since Rust 1.80) runs its closure on the first access and blocks other threads until it is done. `OnceLock` (since 1.70) does the same with an explicit `get_or_init`. Rust has no life before `main` for statics.

**Zig.** The initializer of a container-level variable must be comptime-known. With zig 0.17.1, a run-time value fails with "initializer of container-level variable must be comptime-known". The compiler runs the code and stores the result as bytes in the file.

## Thread-local storage

A **thread-local** variable has one copy per thread: C11 `_Thread_local`, C++ `thread_local`, Rust `thread_local!`, Zig `threadlocal var`, and Odin's `@(thread_local)` attribute. The compiler puts initialized thread-locals in `.tdata` and zero ones in `.tbss`. These two sections form a template. When the runtime creates a thread, it copies the template into a new block for that thread.

Code finds the block of the current thread through a register. On x86-64 Linux, the `fs` segment base points to the thread control block, so a thread-local access is an `fs`-relative load. Go has no thread-local variables: a goroutine can move between threads, so per-thread data would not be per-goroutine data.

## What this means for your code

- **Prefer zero-initialized globals for large buffers.** They cost no file space and no startup time. One nonzero byte moves the whole buffer into the file.
- **Never write through a pointer to a string literal.** Use `const char *` for literals, and copy into an array when you need to change the text.
- **Do not let a C++ global read a global from another file in its constructor.** Use a function-local static, `constinit`, or explicit setup in `main`.
- **Use LazyLock or OnceLock in Rust for computed globals.** They make the first-use cost and the thread safety explicit.
- **Treat static locals as shared state.** They are globals, and threads share them.
